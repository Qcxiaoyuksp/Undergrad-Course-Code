- Java 使用的框架：
  - Spring：解除程序之间的耦合度。提供其他层及框架所需要的对象。
  - SpringMVC：
    - WEB层框架：提供了分层的概念
    - MVC 层概念：
      - Controller：控制层 （承上启下，接收用户请求，调用方法，给用户做想用）--> 封装了 Servlet
      - Service：业务层（业务逻辑的书写、数据的验证、算法的书写...等等）
      - Mapper：持久层（主要就是与数据库打交道。对数据进行 CRUD。   -->  大家曾经 Dao 层。我们使用 MyBatis 框架）
  - MyBatis：
    - 数据持久层的框架。主要是与数据库打交道。 -->  封装了 JDBC 。让其使用更加简单迅捷。
  - SpringBoot：
    - 快速构建 Spring 框架的框架。
    - SpringBoot 的两大优点：
      - 起步依赖：基于 MAVEN 来实现的。
      - 自动装配：项目中其他框架所需要的对象及配置。都可以自动帮我们实现默认配置。若我们想自己配置。则可以传递我们自定义配置来去覆盖掉默认配置。
  - Shiro：
    - 安全框架：
      - 认证：登录 --> 我们的程序要求登录后才能访问呢。否则外人无法访问呢。
      - 授权（鉴权）：可以为方法分配权限。为用户分配权限。只有有对应权限的用户才可以进行访问。
  - Activiti ：
    - 他可以帮我们实现复杂的审批流程。让审批流程变得更加简单化、人性化。
    - Activiti 可以让我们依赖计算机的能力，来实现流程自动的流转。（类似钉钉）。
- 服务器:
  - Tomcat （OK、内嵌了）
  - SpringBoot 中可以内置 Tomcat 并不需要我们去安装即可直接使用。
- 项目的构建及依赖管理：
  - MAVEN：
    - 特点：可以帮我们快速构建项目，同时还可以帮我住我们管理项目中所以需要的依赖。
    - 依赖：项目中所使用的 jar 包。
      - 中央仓 -->  本地仓  --> 项目中
      - 中央仓：一个地址：在国外的要给服务器（一台电脑）。里面搜录了几乎所有常用的 jar 包。我们项目中若使用只需要一点简单的配置即可让计算器自动去这个服务器中实现下载。由于我们访问国外网站非常卡……所以，我们做一个镜像，阿里镜像。
      - 阿里镜像：我们国内的很多大公司。例如 阿里。他们就会做一台服务器。将国外那台服务器中所有的 jar 包都一并镜像到国内这台服务器上。这样我们下载起来就更方便了。
      - 本地仓：我们电脑中的一个文件夹。用来存储中央仓中下载过的 jar 包。（就是老师给大家的 repository 文件夹）。
